# ADR-010：搜索索引投影一致性与相关推荐相似度

**状态**：已接受 ｜ **驱动特征**：上下文边界、数据一致性、可解释性 ｜ **相关场景**：问题检索、详情页相关问题推荐

## 背景

搜索与相关推荐属于 `co-discovery` 上下文的读侧能力，而问题、回答、投票、悬赏等写侧模型分布在 `co-qa` 与 `co-reputation`。检索表 `dis_search_doc` 需要随写侧变化而更新，但 discovery 不能反向依赖写侧上下文的内部表（与 ADR-001、ADR-005 一致）。

事件通过事务性发件箱（ADR-002）投递，可能存在重复投递或重放；若同一事件被投影两次，回答数、得分等计数会被重复累加。此外，详情页相关推荐需要一个不依赖用户行为、可解释且排序稳定的相似度口径，避免与全文检索的相关性打分耦合。

## 决策

1. **由事件投影维护读模型**：`SearchIndexProjector` 消费 QA / Reputation 领域事件，逐事件更新投影文档的对应字段——问题发布写入新文档，问题编辑更新标题与正文，回答提交使回答数 +1，删除问题标记删除、删除回答使回答数 -1，采纳标记 `accepted`，问题投票按「新值 − 旧值」调整得分，悬赏开启 / 授予 / 关闭更新 `bounty_open`。discovery 始终不 join 写侧表。
2. **事件幂等去重**：每个事件先经 `ProcessedEventStore`（消费方标识 `discovery.search-index`）标记已处理；已处理事件直接返回，不重复投影，保证重放或重复投递下计数与得分稳定。
3. **事件语义边界**：回答维度的投票只影响回答自身，不更新问题投影；悬赏关闭 / 授予统一收口悬赏开关，不重复修改得分。
4. **相关推荐采用标签 Jaccard 相似度**：`shared / (sizeA + sizeB − shared)`，候选先按共享标签粗筛，再按「相似度降序 → 得分降序 → 已采纳优先 → 问题 ID 升序」稳定排序并按上限截断；问题无标签或无候选时返回空列表，不抛异常。
5. **查询侧容错降级**：搜索结果作者信息批量补全，缺失用户兜底为「已注销用户」；排序参数非法时回退默认排序，读路径不因脏输入返回 500。

## 后果

- 正面：
  - 读模型与写侧解耦，写路径不感知搜索实现；新增检索形态只影响 discovery 内部。
  - 事件去重守卫使重放、重复投递不会造成计数或得分错误。
  - 推荐相似度只依赖标签，口径可解释、排序确定性强，便于测试与演示。
  - 读路径对作者缺失、非法排序等脏数据有兜底，不把内部异常暴露为 500。
- 负面：
  - 最终一致：投影延迟到事件被消费之后，极端情况下搜索结果短暂滞后于写侧提交。
  - 若事件漏处理，需要依赖事件重放或对账补偿；新增影响检索的写侧事件类型时，必须同步补充投影处理。
  - Jaccard 只比较标签集合，不利用文本相似度或用户行为，推荐精度受标签质量限制。

## 被否决的替代方案

- **写侧服务直接更新搜索表**：会让 `co-qa` 写路径反向依赖 discovery，破坏上下文边界，且跨上下文同一事务写入与 ADR-001 的模块化单体边界决策冲突。
- **定时全量重建索引**：实现最简单，但延迟大、重复扫描成本高，在演示与中等数据量下不满足检索的实时性要求。
- **向量 / 行为相似度推荐**：检索与个性化能力强，但课程规模下既无用户行为数据，也需额外维护向量库与同步链路，与「最小运维面」的 ADR-001 决策冲突。
