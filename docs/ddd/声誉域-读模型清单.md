# 声誉域（Reputation）读模型清单

> 主责：柯博（Ke-1226）｜对应 Lab3 Step 3「聚合识别 · 读模型」
> 与实现代码保持一致：`backend/co-reputation/co-reputation-application`

读模型为查询侧视图，由应用层从聚合/仓储/外部服务（Identity）组装，**不包含可变业务状态**，仅供展示与查询。

---

## 1. BountyView（悬赏列表/详情视图）

| 项    | 内容                                                                                                          |
| ---- | ----------------------------------------------------------------------------------------------------------- |
| 查询用途 | 问题页展示最近一次悬赏（`GET /api/v1/questions/{questionId}/bounty`），无悬赏返回 204                                          |
| 数据来源 | `Bounty` 聚合（`BountyRepository.findLatestByQuestion`）+ `IdentityApi.findUser(sponsorId).displayName`         |
| 组装服务 | `BountyService.latest(questionId)`                                                                          |
| 字段   | `id / questionId / sponsorId / sponsorName / points / status / createdAt / expiresAt / winnerId / answerId` |
| 备注   | 只读返回最近一条悬赏，不暴露冻结中间态，状态以 `BountyStatus` 字符串呈现                                                                |

---

## 2. ReputationProfileView（个人声誉画像视图）

| 项     | 内容                                                                                                                                |
| ----- | --------------------------------------------------------------------------------------------------------------------------------- |
| 查询用途  | 用户声誉档案（`GET /api/v1/users/{userId}/reputation`），含声誉值、徽章；**可用/冻结积分仅本人或管理员可见**                                                      |
| 数据来源  | `ReputationAccount` 聚合（`ReputationAccountRepository.findByUserId`）+ `BadgeRepository.findByUser` + `IdentityApi.findUser(userId)` |
| 组装服务  | `ReputationQueryService.profile(userId, viewerOrNull)`                                                                            |
| 字段    | `userId / displayName / reputation / availablePoints(隐私) / frozenPoints(隐私) / badges[]`                                           |
| 权限    | `viewerOrNull == null` 或非本人非管理员时 `availablePoints` / `frozenPoints` 为 `null`                                                      |
| 徽章子视图 | `BadgeView(type, displayName, description, awardedAt)`，由 `BadgeType` 枚举元数据 + `BadgeAward.awardedAt` 组装                            |

---

## 3. LedgerEntryView（账本流水视图）

| 项    | 内容                                                                        |
| ---- | ------------------------------------------------------------------------- |
| 查询用途 | 声誉流水明细（`GET /api/v1/users/{userId}/reputation/ledger`），分页                 |
| 数据来源 | `LedgerEntry` 聚合（`LedgerRepository.findByUser(userId, PageRequest)`）      |
| 组装服务 | `ReputationQueryService.ledger(userId, viewer, page)`                     |
| 字段   | `id / reason(name) / reason(label) / delta / refType / refId / createdAt` |
| 权限   | 仅本人或管理员（否则 `ForbiddenException` REP-3002）                                 |
| 备注   | 流水只追加，查询天然按时间/ID 有序；`PageResult` 承载分页元数据                                  |

---

## 4. LeaderboardEntryView（排行榜视图）

| 项      | 内容                                                                                                                         |
| ------ | -------------------------------------------------------------------------------------------------------------------------- |
| 查询用途   | 排行榜（`GET /api/v1/leaderboard?period=week                                                                                   |
| 数据来源   | 周/月/学期：`LeaderboardStore.top`（Redis ZSet，由 `ReputationChangedEvent` 增量维护）；全期：`ReputationAccountRepository.topByReputation` |
| 组装服务   | `LeaderboardService.top(period, limit)`                                                                                    |
| 字段     | `rank / userId / displayName / verified / score`                                                                           |
| 用户名/认证 | 由 `IdentityApi.findUsers(userIds)` 批量回填                                                                                    |
| 幂等     | `LeaderboardService.on` 先经 `ProcessedEventStore.markProcessed` 去重再 `store.increment`，重复事件不重复加分                             |

**辅助类型**：

- `LeaderboardPeriod`：枚举 `WEEK / MONTH / TERM / ALL`，其中 `ALL` 不走 Redis，直接按 `ReputationAccount.reputation` 全量排序；
- `LeaderboardStore.Entry`：`(userId, score)` 内部传输结构；
- `RedisLeaderboardStore`：基础设施实现，按 `LeaderboardPeriod` + `AcademicTerm` 键（学期 `2026-FALL`、月 `2026-10`、周 `2026-W41`）写入 Redis ZSet。

---

## 5. 补充：API 摘要视图（非事件风暴读模型，供接口对齐）

- `ReputationSummary`（api 模块）：`(userId, reputation)`，由 `ReputationApiImpl.summary` 提供，供跨上下文调用（如 Q&A / Discovery 展示声誉值）；
- `ReputationApiImpl.reputations(userIds)`：批量 `Map<userId, reputation>`，缺失账户补 0。

---

## 读模型与写模型隔离说明

- 所有读模型仅依赖 `readOnly` 查询（应用层方法标注 `@Transactional(readOnly = true)`）；
- 视图组装不触发写操作、不依赖发件箱/事件总线；
- 排行榜由事件异步增量维护（`ReputationChangedEvent`），允许最终一致；其余视图实时读库。*
